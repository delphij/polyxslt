# Contributing

## Clean-room policy

This project is written from the W3C specifications (XSLT 1.0, XPath 1.0) and the
observable behavior of `xsltproc`.  Do not read the source code of other XSLT or XPath
implementations while working on it, in particular implementations under the GPL or
other copyleft licenses, and do not copy code from them.  Running `xsltproc` to observe
its behavior is fine.

## Principles

- Behavior follows libxslt.  Where the specification leaves a choice to the implementation,
  or where libxslt departs from it, the implementation does what `xsltproc` does.
  Differences that cannot be avoided are recorded in `docs/DIVERGENCES.md`.
- Recent browsers only: the build targets ES2022 without down-leveling or polyfills, and
  uses what the platform provides (DOM, `DOMParser`, `Intl`, Trusted Types).
- No runtime dependencies, and a size budget (see below).

## Layout

```
src/
  xpath/
    parse.ts      tokenizer and parser -> AST
    compile.ts    AST -> closures (no generated source, no eval)
    axes.ts       the XPath data model over the DOM, axes, document order
    fn.ts         core function library (registry)
    value.ts      values and conversions, libxslt's number formatting
    index.ts      compileXPath, evaluate
  xslt/
    compile.ts    stylesheet -> rules and instruction closures; the instruction registry
    pattern.ts    match patterns, default priorities
    avt.ts        attribute value templates
    runtime.ts    context, variable scopes, XPath evaluation, depth limit
    transform.ts  runs a compiled stylesheet
  out/
    finish.ts     output methods; what the html method does to the result tree
    strict.ts     strict mode
    trust.ts      the one place HTML text is parsed; Trusted Types
  host/
    auto.ts       auto mode (the IIFE build)
    processor.ts  XSLTProcessor
  errors.ts       error codes
  index.ts        ESM entry point
```

XPath is implemented here rather than delegated to `document.evaluate`, which cannot bind
variables, cannot be given a context position and size, cannot match patterns, and differs
between engines in edge cases.  `document.evaluate` serves as an oracle in a differential
test instead.

The html output method does not build HTML by serializing and parsing text, as libxslt and
browsers do; it builds the DOM directly and reproduces the effects of that round trip (see
`docs/DIVERGENCES.md`).

## Tests

The reference implementation is Homebrew's libxslt (`brew install libxslt`; the path is
found with `brew --prefix libxslt`, or set `XSLTPROC`).  The version shipped with macOS is
not used.  CI installs the same package on Linux.

- XSLT cases live under `test/fixtures/<feature>/<case>/`.  `in.xml` and `style.xsl` are
  written by hand for the purpose of the test; do not copy stylesheets or documents from
  websites.  `expected.html` or `expected.err` is generated by `pnpm golden` and must not
  be edited by hand; CI checks that the committed files match a fresh run.  The reference
  output is generated with `indent="no"`, since the implementation does not indent.
- XPath cases live in the tables under `test/xpath/`; `pnpm golden` wraps each expression
  in a stylesheet and records xsltproc's result.
- Results are compared as a canonical form of the DOM (`test/support/canon.ts`), after
  parsing xsltproc's output as a browser would.
- All tests run in real browsers (Chromium, Firefox, WebKit) through Vitest browser mode
  and Playwright.  `POLYXSLT_BROWSERS=chromium,webkit` limits the engines.
- `pnpm test:e2e` covers auto mode, including a comparison with the browser's own XSLT
  where it is available.
- Fuzz tests run 300 cases by default; `FUZZ_RUNS=30000 pnpm test` runs more.
- `pnpm test:coverage` measures coverage; keep branch coverage above 90 %.
- `POLYXSLT_PRIVATE=<dir> pnpm verify:private` compares documents and stylesheets kept
  outside the repository, one subdirectory per site, with xsltproc.

Where the implementation deliberately differs from libxslt, record the difference in
`docs/DIVERGENCES.md` and mention it in the test.

## Generated files

`docs/SUPPORTED.md` and `docs/ERRORS.md` are generated by `pnpm docs:gen` from the
registries and from `src/errors.ts`. Regenerate them when adding an instruction, a function
or an error code; CI checks that they are current.

## Size

The bundle sizes are checked by `pnpm size` against 11 KB (brotli); the target is 10 KB and
the hard limit 12 KB.  A new feature either comes with savings that offset its size or
states in its commit message why the bytes are worth it.  Raising the limit needs a
separate reason.
